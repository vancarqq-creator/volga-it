# Practice Automation — UI-автотесты (Java)

Фреймворк UI-автотестов для <https://practice-automation.com/> на **Java 11+, Selenium 4, JUnit 5, Maven, Allure, WebDriverManager**.
Паттерн Page Object Model, только явные ожидания (без `Thread.sleep`), скриншот в Allure при любом падении.
Браузеры: **Chrome** и **Firefox**.

## Запуск

Требования: JDK 11+, Maven 3.8+, установленные Chrome и/или Firefox, доступ в интернет.

```bash
# Установка зависимостей и компиляция
mvn clean test-compile

# Все тесты (Chrome, headless — по умолчанию)
mvn clean test

# Другой браузер
mvn clean test -Dbrowser=firefox
mvn clean test -Dbrowser=chrome

# С видимым окном браузера
mvn clean test -Dheadless=false

# Один класс / один тест / по тегам
mvn test -Dtest=CalendarTests
mvn test -Dtest=AdsTests#closeButtonDismissesAd
mvn test -Dgroups=smoke
mvn test -Dgroups=positive
mvn test -Dgroups=negative

# Другой базовый URL или таймауты (все ключи см. в src/test/resources/config.properties)
mvn test -Dbase.url=https://practice-automation.com -Dtimeout.explicit.seconds=15
```

### Allure-отчет

Результаты пишутся в `allure-results/` в корне репозитория.

```bash
# Сгенерировать и сразу открыть отчет в браузере
mvn allure:serve

# Только сгенерировать статический отчет (target/site/allure-maven-plugin)
mvn allure:report

# Альтернатива, если установлен Allure CLI
allure serve allure-results
```

В отчете: шаги (`@Step`) из Page Object'ов, названия (`@DisplayName`), описания, критичность (`@Severity`),
фичи (`@Feature`) и — для упавших тестов — **скриншот, URL и HTML страницы**.
Прикрепление выполняет `AllureFailureExtension` (JUnit 5) до закрытия браузера.

### CI

В `.github/workflows/ui-tests.yml` настроен запуск в GitHub Actions в матрице Chrome × Firefox;
`allure-results` каждого запуска сохраняются как артефакт сборки.

## Структура

```text
.
├── pom.xml
├── README.md
├── .github/workflows/ui-tests.yml          # CI: Chrome и Firefox
├── allure-results/                         # результаты запусков (в git — только .gitkeep)
└── src/test
    ├── resources/                          # config.properties, allure.properties, junit-platform.properties
    └── java/com/practice/automation
        ├── config/                         # Config (URL, таймауты, браузер), Browser
        ├── core/                           # DriverFactory, DriverManager (ThreadLocal)
        ├── listeners/                      # AllureFailureExtension (скриншот при падении),
        │                                   # AllureEnvironmentWriter (браузер/режим в отчете)
        ├── pages/                          # BasePage, PopupMakerPage, CalendarPage, ModalsPage,
        │                                   # AdsPage, FormPage, PopupsPage
        └── tests/                          # BaseTest, CalendarTests, ModalsTests, AdsTests,
                                            # FormTests, JsDialogTests
```

Принципы: в тестах нет Selenium-локаторов и `driver.findElement` — только вызовы методов страниц и assert'ы (AssertJ);
`BasePage` содержит все обертки над кликами, вводом и ожиданиями; браузер создается на каждый тест и закрывается в `@AfterEach`.

## Надежность

* Только явные ожидания (`WebDriverWait`/`FluentWait`); негативные проверки «элемент не закрылся / значение не изменилось»
  сделаны через `holdsFor(...)` — опрос в течение заданного периода, а не пауза.
* Клик по элементу повторяется, пока его перехватывает анимация или оверлей (`ElementClickInterceptedException`).
* Блок ответа Forminator используется и для успеха, и для общей ошибки валидации, поэтому «успех» определяется по классу
  `forminator-success` / тексту «Thank you», а не по наличию любого сообщения.
* Календарь: если у datepicker есть выпадающие списки месяца и года, переход к нужной дате выполняется через них,
  иначе — кликами по стрелкам с ожиданием смены месяца после каждого клика.
* Глобальный таймаут `junit.jupiter.execution.timeout.default=3m` защищает от зависших тестов.
* При падении (в т.ч. в `@BeforeEach`) в Allure прикладываются скриншот, URL и HTML страницы.

## Важные замечания о тестируемом сайте

* **JS-диалоги (Alert / Confirm / Prompt) находятся на `/popups/`, а не на `/modals/`.** На `/modals/` только два окна
  (Simple Modal и Form Modal). Поэтому сценарии по `/modals/` покрывают кастомные окна, а нативные диалоги вынесены в `JsDialogTests`.
* Календарь `/calendars/` — одно поле даты (jQuery UI datepicker, формат `YYYY-MM-DD`), диапазона дат на странице нет;
  «диапазон» проверяется как последовательный выбор двух дат.
* Реклама на `/ads/` показывается примерно через 5 секунд; ожидание — явное (`timeout.ad.seconds`, по умолчанию 20 с).
* Локаторы построены на стабильных классах плагинов сайта (Popup Maker `pum-*`, Forminator `forminator-*`,
  jQuery UI `ui-datepicker-*`) и видимых текстах. Если сайт изменит разметку, правки нужны только в классах `pages/`.
* Тесты формы отправляют реальные данные в форму практического сайта (тестовые значения).
